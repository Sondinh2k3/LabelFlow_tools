# M2 Windows functional measurements

Measured 2026-11-07 on the same reference machine as M1: Windows 10.0.26200 x64, Intel Core i5-12500H (16 logical processors), 15.64 GiB RAM; Node 22.20.0, Rust 1.99.1, local FFmpeg/FFprobe 9.0.2. Desktop tests use WebView2 and embedded assets, not Vite.

| Scenario                                    | Measured result                     | Scope                                                                                                                                                                                              |
| ------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 10k synthetic PNG incremental import, debug | 399.87 s                            | Cancel after 100 committed images, preserve one annotated image, resume 9,900, then deduplicate all 10,000 on repeat; 20,100 progress events                                                       |
| Same 10k workflow, release                  | 234.20 s                            | Final schema 3; same source files; generated annotations preserved; excludes build time and fixture creation                                                                                       |
| Full video acceptance, final Rust debug run | 8.01 s                              | Three H.264 MP4s, PTS index, VFR/B frames, verified 90° rotation, manual/interval extraction, duplicate/cancel checks, JPEG decode and both exports; excludes compilation and external parser time |
| Independent PNG frame validation            | 37/37 pixel-exact                   | Compared against a complete sequential FFmpeg RGB decode without a frame-select filter; integer PTS compared with independent FFprobe fixture output                                               |
| COCO API validation                         | 148 annotations; 74 exact RLE masks | Polygon/components and compressed RLE load; RLE pixels/area match the canonical fixture                                                                                                            |
| Official YOLO parser validation             | 37/37 image-label pairs             | Unmodified label verification functions and NumPy helpers at pinned commit; no full training run                                                                                                   |
| Packaged Tauri process restart              | 37/37 documents and masks exact     | Native IPC, immutable mask files, real SQLite, duplicate extraction, H.264 playback, VFR exact preview and QA wizard                                                                               |

The 10k files are small, distinct 16×12 grayscale PNGs, deliberately testing record count, durable incremental writes, cancellation, resume, deduplication, pagination and source preservation. They are not representative 1080p decoding/thumbnail throughput. Clock starts after fixture creation and includes source scanning, decode/hash, thumbnail work, SQLite FULL durability, job progress, annotation save, resumed import and repeated import. These functional runs were not isolated benchmarks: other verification/build work occurred during the session and filesystem cache was warm for the release run. No direct performance improvement ratio is inferred.

Raw results: `.cache/m2-large/debug.json`, `release.json`, `latest.json`; `.cache/m2-acceptance/latest.json`, `parsers.json`, `desktop.json`. Scripts and preparation are documented in README. The 10k acceptance project can be opened independently for manual inspection; original media and the real M1 dataset remain unchanged.

No new claim is made about startup p50/p95, preloaded 1080p switch latency, 60 FPS, dense-mask interaction latency, or total WebView process memory. A sample backend working set is insufficient to establish the desktop <400 MB target. Exact frame decode still starts from the beginning of a clip; sparse preview near the end of long videos can be slow. M5 remains the place for a measured keyframe-seek/cache/render optimization campaign.

Fixtures contain generated patterns, not real street footage or human-reviewed ground truth. Video/geometry correctness and parser acceptance have been measured; semantic validity of labels for a real training task has not.
