# Dependency inventory — M1

M1 adds `png 0.18` as a direct dependency (already transitive through `image`) to preserve grayscale/indexed class IDs without color conversion. No new frontend runtime dependency.

The [machine-readable inventory](dependency-inventory.json) covers 200 installed npm packages and 270 fetched Rust crates on Windows x64, including development/build dependencies. Regenerate after dependency changes:

Set `CARGO_HOME` when the registry is outside `.tools/cargo`. The script records missing registry entries rather than guessing licenses.

## M2 additions

M2 adds no npm or Cargo runtime dependency. FFmpeg/FFprobe are external, user-installed tools, not bundled with LabelFlow. This development machine uses FFmpeg 9.0.2 essentials from Gyan; downloaded archive SHA-256 `60f467265b1e312373dbcd92200c2618a74850f98d3d078e94296bb3fa2047ba` was verified against the provider's published checksum. The ignored development tools are not distribution artifacts.

Optional acceptance-only dependencies: Pillow 13.0.0, pycocotools 2.0.11 and NumPy 2.5.4 in `.cache/python`; PyYAML is used by the export validator. They are not imported by the desktop runtime. The official Ultralytics label verification functions and their NumPy helpers are fetched into ignored cache at commit `3cd02542899c1bcab5690b02033bc18aa07df0d4`; recorded source hashes are verified before executing selected, unchanged AST functions. The AGPL source is not copied into application sources or bundled. This validation does not install Torch, train models or run inference. COCO API validates polygon/RLE loading independently of LabelFlow's implementation.

No fresh npm advisory scan or Ubuntu distribution audit is claimed for M2. Existing inventory and lockfiles remain authoritative for the Windows application dependencies; a release installer still needs its own notice/license packaging review.

## M3 additions

No npm/Cargo runtime dependency was added. The executable embeds only the project's two Python worker source files. The Python interpreter, ONNX Runtime, NumPy, Pillow and trained weights are not bundled or automatically downloaded. Optional local inference testing used Python 3.12, ONNX Runtime 1.31.1, NumPy 2.5.4 and Pillow 13.0.0 in an ignored workspace environment; ONNX 1.23.2 is fixture-generation-only. Preserve the distributions' license notices if distributing a separate environment: [ONNX Runtime (MIT)](https://github.com/microsoft/onnxruntime/blob/main/LICENSE), [NumPy (BSD and bundled-library notices)](https://numpy.org/doc/stable/license.html), [Pillow (installed 13.0.0 metadata: MIT-CMU)](https://pillow.readthedocs.io/en/stable/about.html#license), [ONNX (Apache-2.0)](https://github.com/onnx/onnx/blob/main/LICENSE).

The tiny Conv/Constant ONNX files in `tests/fixtures/ai` are generated by `scripts/create-ai-fixtures.py`; they contain no trained third-party weights and are not embedded in the release executable. Model manifests record a user-supplied license identifier/statement as provenance; LabelFlow does not determine or grant a model's redistribution rights. No trained model has been supplied for this milestone, and no model quality or GPU compatibility is claimed.
