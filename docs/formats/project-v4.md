# Project format — schema 4 (M3)

Manifest format remains 1. Database schema becomes 4. The existing migration mechanism backs up a schema-3 database before transactionally adding `ai_suggestions` and updating `projects.schema_version`. Media IDs, profiles/classes, annotation documents, revisions, video frame references, mask assets and operation logs are unchanged. Tests also exercise schema 1/2 upgrades through all migrations. Older applications reject schema 4; downgrade is not automatic. Preserve the complete project before returning to an older version; the pre-migration DB backup does not contain edits made after migration.

`ai_suggestions` contains UUID `id`, `media_id` FK, `base_revision`, `source_sha256`, validated `prediction_json`, `status` (`pending`, `accepted`, `rejected`), creation/review times, and nullable `accepted_revision` / unique `operation_id`. Accepted status requires both revision and operation ID; other statuses require both null. An index supports media-scoped review history. Full prediction JSON carries model identity/version/SHA/license, class map, geometry, confidence, CPU provider/device and processing time. Semantic mask RLE uses model class indices; preview/approval maps them explicitly to the profile's export IDs.

Pending/rejected rows are never normal annotation documents or export inputs. Preview constructs transient overlay objects using `model_suggestion`; the regular document saver rejects that source. Acceptance converts box sources to `model_approved` and composites semantic masks by filling only current ignore values. Normalized composite semantic rows are marked `model_approved` for the acceptance revision. That revision and before/after operation log link to the original immutable suggestion, including where manual pixels were retained. Review audit remains after undo or later manual revisions.

Approval updates annotation document, mask references, normalized rows, revision, operation log and suggestion status in one SQLite transaction. Mask assets remain immutable external PNGs under the existing schema-2/3 storage contract. Suggestions use SQLite payloads, so ordinary project backup/restore already covers them. There are no Python paths, model weights or worker settings in a project/backup.

Application configuration adds `ai.json` containing user-selected absolute interpreter and manifest paths; these settings do not auto-start a worker. Hash-keyed embedded worker source copies are discardable application runtime files. Images and model source files are never modified by LabelFlow.
