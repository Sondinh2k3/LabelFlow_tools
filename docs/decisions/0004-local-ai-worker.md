# ADR 0004 — Optional local AI suggestions

Status: accepted for M3. No cloud, inference server, training, model download, GPU dependency or M4 road workflow is introduced.

`src/features/ai` owns the dialog and separate overlay. `src-tauri/src/commands/m3.rs` coordinates native selection and scoped image preparation. `src-tauri/src/ai/{protocol,worker,suggestions}` owns typed responses, worker lifetime and persistence/review. `worker/{main,adapters}.py` implements the versioned stdio protocol and explicit ONNX schemas. Existing editor, geometry, autosave, import/export and video modules remain reusable.

A worker is an explicit session, never a required desktop dependency. The chosen interpreter and manifest live in local app settings, not project metadata. Worker sources are embedded and extracted under a content hash; executable/arguments cannot arrive from frontend prediction calls. The optional dependency environment and model files are supplied separately. See the [worker contract](../../worker/README.md).

Inference runs on a blocking worker thread **outside the project session mutex**. The project lock is held briefly to capture canonical source identity and document revision, and later to validate/store a suggestion. This lets cancellation and manual saves remain responsive to IPC. One supervised process has one in-flight request; 25 ms receive polling, generation tokens, bounded lines/queues, deadlines, kill/wait and joined reader threads define failure recovery. A worker error cannot invoke the annotation save path. Closing a project cancels and stops its worker. The parent pipe watcher prevents idle workers from surviving parent termination.

Schema 4 adds a separate `ai_suggestions` table. Prediction creation and rejection never change the normal annotation document, normalized annotation rows or mask assets. Export reads only normal documents. Suggestions store the full validated prediction and immutable provenance in SQLite, so existing DB+mask backup/restore includes them without introducing untracked files.

Approval requires an explicit suggestion ID, current document revision equal to its base revision, unchanged original source identity and a non-approved document. It appends boxes with `source=model_approved`, or fills semantic ignore pixels without changing human values. Review becomes `needs_review`. The resulting document, operation log and suggestion's accepted revision/operation ID commit in **one transaction**. A failure rolls all database changes back; immutable orphan mask files follow the existing recovery policy. Semantic composite rows are marked model-approved on that transaction, while the full original prediction and the before/after operation log retain provenance. Subsequent manual edits and undo create normal new revisions; the review audit is retained, rather than pretending the historical AI approval did not occur.

No destructive replacement mode is offered. A stale prediction must be rejected and regenerated; reopening an approved image for review also changes its revision, requiring a fresh prediction. This intentionally favors straightforward protection over complex merging across concurrent revisions. Only one image is predicted per request in M3. Suggestion history is bounded to 100 entries in the UI, pending first, with at most ten pending suggestions per image; older review history is retained in SQLite.

PIDNet is a constrained adapter contract with actual dry-run schema checks, not an assertion that arbitrary PIDNet checkpoints can be loaded. The user has no trained ONNX model yet; fixture tests verify runtime interoperability and protection, not semantic accuracy. Prompt masks are not advertised by unsupported models. Real model quality, target-machine throughput and specialized road review remain future validation/M4 work.
